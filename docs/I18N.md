# Localisation (i18n) - conventions and glossary

WinCreative ships **English** and **Русский**. The language is chosen in *Actions > Preferences > Interface > Language / Язык*
(`System default` follows the OS language via `navigator.language`), stored in `prefs.language` (`'auto' | 'en' | 'ru'`) and switches
**live, without a restart**. Adding another language later = one more `locales/<lang>/` folder + one entry in `LANGS`.

## 1. API (`src/renderer/src/i18n/index.ts`)

| Call | Use |
|---|---|
| `t(key, params?)` | Translate now. `{name}` placeholders are replaced from `params`. A numeric `params.count` picks the plural form. |
| `tk(key, params?)` | *Lazy reference*: pass it where a string attribute/child/label is expected; it is translated when rendered **and again on every language change**. |
| `tEl(el, key, params?)`, `tAttr(el, 'title'\|'placeholder'\|'aria-label'\|'data-tip'\|'label'\|'alt'\|'value'\|'html', key, params?)` | Imperative equivalents; they write `data-i18n*` attributes so the element is re-translated automatically. |
| `translateDom(root?)` | Re-translate all `data-i18n*` elements (called by `setLang`). Static HTML may use `data-i18n="key"`, `data-i18n-title`, `-placeholder`, `-aria-label`, `-tip`, `-label`, `-html` (+ `data-i18n-params='{"n":3}'`). |
| `onLangChange(cb)` / `bindLang(cb)` | Subscribe (`bindLang` also runs `cb` immediately). Returns the unsubscribe function. Use for content built from plain `t()` calls. |
| `getLang()`, `setLang(lang)`, `LANGS`, `detectLang()`, `resolveLang(pref)` | Language state. `prefs.language` drives it (`i18n/boot.ts`). |
| `resolveText(x)` | `string \| tk() ref \| () => string` -> string. A plain string that is a known key is translated, any other string passes through (legacy literals keep working). |
| `has(key)`, `tIn(lang, key)`, `inLang(lang, fn)` | Existence test / translate in a fixed language (e.g. English matching). |
| `registerDictionary(lang, dict)` | Add keys at runtime. |

Lookup order: `ru[key]` -> `en[key]` -> the key itself (one `console.warn` per key in dev). Plural lookup: `t('x.count', {count: n})` uses
`Intl.PluralRules(lang)`; keys `x.count_one`, `_few`, `_many`, `_other` (en: `_one` + `_other`; ru: all four; `{count}` may be omitted in
`_one` texts such as "one file"). Numbers you want formatted must be formatted by the caller (`{n}` is inserted verbatim).

### Registries accept text sources
* `MenuItem.label`, `PanelDef.title`, `ActionDef.label`, `PopoverOptions.title`: **key string, `tk()` ref, `() => string`, or literal**.
  Always read them through `resolveText(x)`, `actionLabel(a)`, `actionCategory(a)`, `menuItemParts(item)`.
* `MenuItem.group` (`'add' | 'video' | 'canvas' | 'share'`) puts an Actions-menu item under a small heading; write the label **without**
  the prefix. Old English labels `'Add: ...'` still group automatically.
* `ActionDef.category` stays a stable id (`'Tools'`, `'Layers'`, ...); the heading is `core.category.<id>` (add one for a new category).
* `findMenuAction(regex)` (cross-module aliases like Copy/Paste) matches the **English** label (`inLang('en', ...)`), so keep an English
  label reachable: use `tk('layers.menu.copy')` whose English text is `Copy`, not a computed string.
* `h()` (`ui/dom.ts`): any of `text`, `title`, `placeholder`, `aria-label`/`ariaLabel`, `data-tip`, `label`, `alt`, `value` may be a `tk()`;
  a `tk()` child becomes `<span data-i18n>`. Elements that mix text and child elements (icon + text) keep their children: only the element's
  own text node is replaced.
* `PopoverHost` re-runs the build function of the open popover on a language change, so panels rendered with plain `t()` refresh too.
* Tooltips: the tooltip layer moves `title` to `data-tip` after the first hover; `tk` handles both (never read/write `title` by hand).

### Main process
`src/main/i18n.ts`: tiny dictionary `mt(key)` for window titles and native dialog titles ("Save", "Open", folder picker, projector window).
The renderer pushes its language with `window.brushwork.setLanguage(lang)` (IPC `i18n:set`). Native dialog **filters** (`{name: 'PNG image'}`)
come from the renderer: translate them with `t()`. `BW_LANG=ru|en` forces the start-up language; **all self-test runs (`BW_*TEST*`) force English**
(`--bw-lang=en`, exposed as `window.brushwork.bootLang`), so tests may keep querying English text.

## 2. Files and ownership (parallel-safe)

```
src/renderer/src/i18n/
  index.ts            runtime (t, tk, tEl, translateDom, setLang, ...)
  boot.ts             prefs <-> language <-> main process wiring (called first in main.ts)
  locales/en/<module>.ts   flat Record<string,string>   \  one file per module - an agent only ever edits
  locales/ru/<module>.ts   flat Record<string,string>   /  the two files of the module it converts
  locales/{en,ru}/index.ts registry (already lists all modules)
src/main/i18n.ts      main-process dictionary
tests/i18n.test.ts    dictionary consistency (see below)
scripts/i18n-check.mjs  `npm run i18n:check`
```

Modules: `core` (app shell, shared words, action names, `core.common.*`, `core.category.*`), `ui` (top bar, sidebar, popover, new-canvas dialog),
`brushes`, `layers`, `color`, `gallery`, `adjustments`, `selectxform`, `guides`, `animio` (also `psdimport`), `interface` (prefs, cheat sheet,
help, QuickMenu, diagnostics), `tutorial`. `features/profiles` -> `color`. A module dictionary file looks like:

```ts
const dict: Record<string, string> = {
  'layers.menu.mergeDown': 'Merge down',
  'layers.count_one': '{count} layer',
  'layers.count_other': '{count} layers'
}
export default dict
```

## 3. Key naming

`<module>.<area>.<name>` in camelCase, English-derived, stable: `layers.menu.mergeDown`, `layers.panel.title`, `layers.toast.locked`,
`brushes.studio.hardness.tip`. Suffix conventions: `.tip` tooltip, `.hint` secondary line, `.placeholder`, `.confirm` confirm() text,
`.toast` notification, `.title` dialog/panel title, `_one/_few/_many/_other` plural. Rules:
* The test enforces the prefix = module name and that no key is defined twice.
* **One key per full sentence.** Never concatenate translated fragments; use `{params}`: `'Delete "{name}"?'`.
* Reuse `core.common.*` (ok, cancel, done, close, save, create, delete, apply, reset, add, remove, rename, duplicate, yes, no, open, import,
  export, none, on, off, back, next, confirm, name, untitled, error, loading, copy, paste, select, more, opacity, size) instead of new keys.
* Brand and technical names are not translated and are written literally in the strings: WinCreative, QuickShape, QuickMenu, ColorDrop,
  StreamLine (with a Russian explanation where needed), PNG, JPEG, PSD, ICC, DPI, FPS, Windows Ink.
* Keep `Ctrl+Z`, `(B)` key hints in the string (they are the same in both languages).
* Do not translate identifiers, `data` values, file extensions, ids, CSS classes, saved document/brush/palette names or preset ids.
  User content stays as the user typed it. If a *built-in* content name is shown (built-in brush, palette, blend mode, adjustment), look it up by
  id: `t('brushes.builtin.' + id)`, falling back to the stored name when the key is missing (`has(key) ? t(key) : name`).
* Dynamic strings whose value changes while shown (counters, sizes) must be set with `t()` at update time, not with a static `tk` params object.
* `{count}` is the only reserved param (plural selector). Params must be identical in both languages (tested).

## 4. How to convert a module (recipe)

1. `npm run i18n:check -- <module>` lists the remaining literals (`file:line: text`). Skip false positives with a trailing `// i18n-ignore`.
2. For each literal choose the API:
   * `h('button', { text: 'Save', title: 'Save (Ctrl+S)' })` -> `h('button', { text: tk('layers.save'), title: tk('layers.save.tip') })`
   * `el.textContent = 'x'` set once -> `tEl(el, 'k')`; set repeatedly with values -> `el.textContent = t('k', {n})` inside an update function
     that is also called from `onLangChange`.
   * `MenuItem.label: 'Merge down'` -> `label: tk('layers.menu.mergeDown')`; grouped items: `group: 'add', label: tk('animio.menu.insertFile')`.
   * `registerAction({ label: 'Group layers', category: 'Layers' })` -> `label: tk('layers.action.group')`.
   * `notify('Layer locked')` / `toast()` / `confirm('Delete?')` / `askText('Title', ...)` -> `notify(t('layers.toast.locked'))` etc.
   * `select`/`option` lists: `h('option', { value: id, text: tk('adjustments.blend.' + id) })`.
   * Panels/dialogs built once inside `render(body)` may use plain `t()`; a language change while they are open re-runs `render` for popovers.
     For long-lived DOM (docks, floating panels, overlays) use `tk`/`tEl` or subscribe with `onLangChange`.
   * Native dialog filters: `filters: [{ name: t('animio.filter.video'), extensions: ['mp4'] }]`.
   * Errors shown to users: `t('x.error', { error: e.message })`; `console.*` and `throw new Error(...)` stay English.
3. Add every key to `locales/en/<module>.ts` and a Russian text to `locales/ru/<module>.ts` (same keys, same `{params}`).
4. `npx tsc --noEmit`, `npx vitest run tests/i18n.test.ts` (lists missing/orphan keys and param mismatches), `npm run i18n:check -- <module>`
   (also reports `t('...')` keys that do not exist), then look at the UI in Russian: `node qa-i18n.mjs` (isolated profile, screenshots to
   `qa-screens/i18n`, switches language live). Russian is 20-30 % longer: check buttons, tab bars, slider rows and menus for overflow; fix with
   CSS (`min-width:0`, `flex-wrap`, `text-overflow`) rather than by shortening the translation to something unnatural.
5. Do not change behaviour: selectors used by self-tests are queried in English (tests run with `--bw-lang=en`).

Layout hints: use `white-space: normal` + `min-width: 0` in flex rows, avoid fixed pixel widths on buttons with text, prefer `max-width` with
ellipsis on labels, keep icon-only where a word would not fit.

## 5. Russian style

* Sentence case, no trailing period on buttons/labels, `…` (U+2026) instead of `...` for "opens a dialog".
* Imperative infinitive for commands in menus/buttons ("Сохранить", "Удалить слой"); nouns for panels and settings ("Слои", "Величина стабилизации").
* Use «ёлочки» quotes, `ё` where it removes ambiguity (слоёв, тёмная).
* Units: `px` stays, `%`, `мс` (ms), `°`, `дюйм`, `см`, `мм`. Dimensions `{w} × {h}`.
* Plurals: always provide `_one/_few/_many/_other` (1 слой / 2 слоя / 5 слоёв / 1,5 слоя -> `other`).
* Do not calque: prefer the wording of Photoshop / Krita / Procreate Russian UI (glossary below). If a term is missing, add it to the glossary
  in the same commit.

## 7. Checks

* `npx vitest run tests/i18n.test.ts` - every en key exists in ru (lists the missing ones), no orphan ru keys, `{params}` match, plural groups
  complete (en one/other, ru one/few/many/other), keys carry the module prefix, no duplicates, runtime plural/fallback behaviour.
* `npm run i18n:check [-- --list | <module> | --strict]` - heuristic scan for remaining hard-coded English (text/title/placeholder/label,
  `.textContent =`, `notify/toast/alert/confirm/prompt/askText(...)`, `h('tag', ..., 'literal')`, `innerHTML`) per module, plus `t()`/`tk()` keys
  that are missing from `locales/en`.
* `node qa-i18n.mjs [--lang ru|en] [--out out-i18n]` - launches the built app in an isolated profile, screenshots menus, panels, cheat sheet,
  new-canvas dialog and every Preferences tab, and switches language live. Look at the pictures.
